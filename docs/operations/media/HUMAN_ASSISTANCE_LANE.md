# Human Assistance Lane

Status: CANONICAL MEDIA OPERATIONS
Version: 1.0
Date: 2026-10-15

## Purpose

Give the studio a deliberate way to ask for human help when human intervention is the safest, fastest or only practical way to unblock production.

Human assistance is **on demand**. It is not a permanent approval layer and must not turn the studio into a manually operated workflow.

## Operating principle

**Ask for the smallest human action needed, then return control to the studio.**

## Who coordinates it

Media Producer / Production Coordinator.

A request may originate from:
- Producer;
- Showrunner;
- Technical Operator;
- the craft function active in the current stage.

## Eligible helpers

Depending on the task:
- Owner;
- trusted local operator;
- domain expert;
- craft specialist;
- technician/vendor support.

## When to ask for help

Valid triggers include:
1. automated or application recovery is exhausted;
2. a physical-world action is required;
3. login, credentials or identity-bound action is required;
4. a specialized craft capability is unavailable;
5. visual/audio judgment remains materially uncertain;
6. domain expertise is missing;
7. rights/source confirmation requires human contact;
8. a bounded human action is materially faster and lower-risk than more automation.

## Human Assistance Request Packet

Every request must state:
- request ID;
- episode and stage;
- why help is needed;
- exact human task;
- last verified state;
- project/artifact reference;
- allowed scope;
- **do not change** boundary;
- expected return artifact/action/answer;
- acceptance criteria;
- exact return handoff.

A request like “fix the video” is invalid.

A request like “open Premiere, relink these two missing media files only, save as v014, do not change cuts or effects, then report the saved project path” is valid.

## Authority boundaries

Human assistance does not grant:
- publication authority;
- permission to spend money;
- permission to subscribe or purchase;
- permission to use credentials/identity;
- permission to share private material;
- permission to make irreversible changes.

Those remain subject to their normal Owner/authority gates.

## Return to automation

After the human action:
1. verify the return against acceptance criteria;
2. save a new checkpoint;
3. record outcome and human time used;
4. resume from the declared return handoff;
5. do not repeat completed human work.

## Recurring-gap rule

If the same human-help cause occurs three times, open a capability review.

Possible fixes:
- acquire or configure a better tool;
- train the workflow;
- create a safe automation;
- redesign the handoff;
- add or retain a human specialist if it is economically justified.

The goal is not “zero humans.”
The goal is to use humans where their judgment or physical access adds value, without making preventable manual work permanent.
