# RevenueSystem 2.0 — Art Direction Lock
Version: 1.0
Date: 2026-10-17
Status: ART_DIRECTION_LOCK_CANDIDATE
Source identity: Studio — Editorial Renaissance Motion

## 1. Governing decision

RevenueSystem 2.0 uses the **same cultural/visual identity DNA as the Studio**.

This means:
- no separate Babylonian/Baghdadi design language;
- no generic Windows-enterprise visual identity;
- no independent RevenueSystem palette competing with the Studio.

The application translates **Editorial Renaissance Motion** from moving editorial media into a dense professional financial desktop environment.

## 2. Locked palette

Dominant:
- Paper Ivory / white-light: `#F6F1E8`

Structural:
- Cobalt: `#174FA6`
- Clear Blue: `#2B73C9`
- Sky Blue: `#8EACD2`

Accents:
- Brass Gold: `#B58A3E`
- Deep Forest: `#173C32`

Support:
- Warm Parchment: `#D9C8B1`
- Charcoal: `#151515`

Rules:
- Paper Ivory dominates the shell and primary work surfaces.
- Cobalt builds structure, active navigation, focus and primary commands.
- Brass is annotation/high-value emphasis, never a general button color.
- Deep Forest is positive/verified/matched state.
- Charcoal is text/anchor only; dark-first UI is not the default.
- red remains reserved for financial difference/risk/destructive state and is a semantic exception, not part of decorative identity.

## 3. Typography

Arabic:
- identity/display moments: refined Naskh/editorial influence;
- operational UI/data: high-legibility modern Arabic sans.

Latin:
- editorial display only when identity needs it;
- operational UI/data: modern sans.

Financial numbers:
- tabular;
- strong baseline alignment;
- signs and currency identity remain explicit;
- no ornamental numeral treatment.

## 4. UI materiality

Allowed:
- paper-ivory warmth;
- subtle grain in non-data surfaces;
- editorial rules/lines;
- cobalt structural frames;
- small brass annotations;
- layered paper-like panels;
- soft depth through overlap rather than heavy shadows.

Not allowed:
- faux antique paper;
- historical ornament as decoration;
- classical statues/cutouts inside transaction screens;
- botanical art behind tables;
- heavy textures behind data;
- glassmorphism;
- neon/cyberpunk;
- generic blue SaaS cards.

## 5. Composition

Studio rule translated to UI:

Video:
- 35–55% negative space;
- one hero object.

Application:
- negative space is preserved in shell, onboarding, empty states, selected-item inspector and overview states;
- dense operational regions may intentionally use lower negative space;
- each workspace must still have one dominant task region;
- subordinate panels must visibly recede.

The interface must never become a wall of equally weighted cards.

## 6. Workspace-specific art direction

### Day Console
Editorial ledger wall:
- ivory field;
- branch/cashier structure defined by cobalt rules;
- brass micro-annotations for attention;
- deep-forest closure readiness;
- one strong operational focal region.

### Cashier Workbench
Counting desk / financial workbench:
- tightly structured entry matrix;
- paper/ivory workspace;
- cobalt focus paths;
- brass used for denomination/context annotation;
- visual rhythm inspired by editorial tabulation, not spreadsheet default styling.

### Reconciliation Studio
Investigation dossier:
- selected cashier behaves like an editorial evidence dossier;
- cobalt structural lines connect source → cash → electronic → adjustment → account → difference;
- brass marks explain exceptional adjustments;
- difference becomes the visual hero when non-zero;
- zero difference resolves into deep-forest verification.

### Finance Ledger
Editorial ledger:
- account identity is treated like a dossier heading;
- transactions read as a refined ledger, not generic CRM;
- documents/evidence use layered paper treatment.

### Reports Center
Most literal translation of Studio language:
- ivory report paper;
- cobalt hierarchy;
- brass annotation;
- refined editorial Arabic headings.

### Data Operations
Editorial process sheet:
- staged import/validation reads like a structured production/evidence workflow;
- issues use annotation language rather than generic warning-card stacks.

### Administration
Technical appendix:
- restrained;
- more structural than expressive;
- identity remains in palette, typography, rules and materiality.

## 7. Motion grammar

Borrow from Studio motion language:
- page shifts;
- panel/object wipes;
- line-builds;
- semantic transitions;
- foreground occlusion;
- restrained match cuts between workspace contexts;
- cobalt reset moments.

For UI:
- 120–220 ms micro-interactions;
- 180–320 ms panel/inspector transitions;
- longer motion only for major workspace-state changes;
- animation never blocks typing or financial entry.

Cinetic may prototype these motions.
WPF/Blend remains implementation authority.

## 8. Cultural identity test

A RevenueSystem frame passes only if:
1. it unmistakably belongs to the same visual family as the Studio;
2. it still reads as professional financial software;
3. it does not rely on classical/video-specific imagery to signal the identity;
4. the palette/material/typography/composition carry the identity on their own;
5. dense data remains easier to read than before;
6. it does not look like generic Fluent/SaaS enterprise UI.

## 9. Rejected previous direction

The proposed independent direction:
**Baghdad Financial Modernism**

is withdrawn.

Reason:
The owner requires cultural identity to match the existing Studio. A second independent cultural system would fragment the broader visual ecosystem.
