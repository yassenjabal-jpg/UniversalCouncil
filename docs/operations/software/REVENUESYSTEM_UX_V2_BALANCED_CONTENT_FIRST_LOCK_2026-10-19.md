# RevenueSystem 2.0 — UX v2 Balanced Content-First Direction Lock
Date: 2026-10-19
Status: OWNER APPROVED / ACTIVE

## Decision

The owner approved the UX v2 direction:

**BALANCED CONTENT-FIRST**

This direction becomes the required composition model for the current Section 1 remediation and for later RevenueSystem workspaces unless explicitly changed by the owner.

## Identity decision

The visual identity is **not rebuilt from zero**.

The approved identity remains:

**EDITORIAL FINANCIAL ENGRAVING**

What changes is the composition system, not the identity constitution.

## What is preserved

- Paper Ivory / Deep Forest / Cobalt palette family.
- Editorial Financial Engraving.
- Guilloché as restrained authored material.
- Ledger rules.
- Compact institutional seals.
- Arabic editorial typography.
- Large disciplined financial numerals.
- Native WPF implementation.
- No banknote skins.
- No architecture branding.
- No national/government identity drift.
- No neon/glass/casino/SaaS card-wall drift.

## What must be rebuilt

The following composition layers require rework:

1. Shell chrome and top-context architecture.
2. Removal of duplicate WorkItem/page title strip.
3. Header hierarchy.
4. Hero sizing.
5. Local section-header density.
6. Status-bar density.
7. Cashier task-first composition.
8. Day readiness-first composition.
9. Finance account-dossier/ledger composition.
10. Shared compact-header primitives.

This is a **composition rebase**, not a brand restart.

## Screen direction

### Cashier
Highest-density operational surface.
Order:
1. compact operator identity/context;
2. IQD coarse / change / USD totals;
3. denomination matrix;
4. save/recovery state;
5. secondary navigation.

No oversized hero.

### Day
The dominant semantic object is:
**ready / not ready / review required**

The page title must never overpower operational readiness.

### Finance
Compose:
- account identity;
- account status;
- key balances/KPIs;

as one compact dossier block, followed immediately by the transaction ledger.

Avoid:
header → KPI header → ledger header stacking.

## Shell rule

Target:
**Windows title → one compact financial context ribbon → workspace**

No dedicated duplicate page-title strip.

At compact 1024×720:
- persistent top chrome <= 58px;
- persistent bottom bar <= 24px;
- high-frequency hero <= 78px;
- normal hero <= 90px unless UX v2 approves an exception.

## Art rule

Removing bars must not flatten the product.

Identity moves into:
- typography;
- guilloché;
- fine border rhythm;
- registration/ledger marks;
- compact seals;
- denomination treatment;
- spacing and composition.

**Fewer bars, stronger authorship.**

## Rework classification

Historical Section 1 technical/behavioral evidence remains valid.

Required rework:
**PARTIAL VISUAL/COMPOSITION REBASE**

Not required:
**FULL PRODUCT OR IDENTITY RESTART**

No Section 2 opening and no merge to RevenueSystem main are authorized by this decision alone.
