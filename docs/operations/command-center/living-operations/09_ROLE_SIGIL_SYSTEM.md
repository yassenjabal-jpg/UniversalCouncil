# UniversalCouncil Role Sigil / Member Identity System

Status: STUDIO-SUPERVISED COMPONENT IDENTITY CONTRACT  
Canonical visual authority: the eight pinned reference images

## Purpose

Role Sigils are the primary visual identity of Council/Studio members and functions inside Living Operations.

In the product experience, a Sigil must feel like a **recognizable member identity**: the Owner should be able to distinguish who is participating, what that member contributes, what state it is in, and what opens when it is selected.

This member-like identity is expressed through:
- a persistent glyph;
- a persistent role label;
- a concise functional subtitle;
- a restrained identity tint;
- an operational state ring;
- optional reasoning rings;
- optional truth/blocker badge;
- routing/relationship paths when relevant;
- a consistent Role Context destination;
- recent contributions to the current project.

A Sigil is not a decorative icon.

It is also not permission to invent a photographic person, cartoon mascot, or unsupported autonomous agent. Distinctiveness comes from function, glyph, color, state, motion and interaction.

## Canonical fidelity precedence

The pinned reference images govern visible appearance.

The visible reference glyphs and colored circular medallions must be preserved where they appear. Semantic concept descriptions in this file explain meaning only; they do **not** authorize replacing a visible reference glyph with newly invented geometry.

When text and image disagree on appearance:
**canonical reference image wins.**

## Family grammar

All Role Sigils / member medallions share:

- one recognizable identity glyph;
- one outer semantic/state ring;
- optional reasoning rings;
- optional truth/blocker badge;
- one role label;
- one short role/function subtitle at expanded sizes.

Base constraints:

- readable at 20–24px;
- recognizable at 40–48px;
- expressive at 64–80px;
- no photographic portrait dependency;
- no cartoon body;
- no color-only identification;
- no decorative icon without a semantic destination;
- no invented replacement glyph when a canonical reference glyph exists.

## State layers

Layer 0 — member identity glyph  
Layer 1 — stable identity tint / medallion family  
Layer 2 — operational state ring  
Layer 3 — reasoning depth rings when applicable  
Layer 4 — truth/attention/blocker badge  
Layer 5 — transient motion cue when state changes  
Layer 6 — routing/relationship path when relevant to current work

Supported operational states:

- IDLE
- ACTIVATED
- WORKING
- REVIEWING
- WAITING
- BLOCKED
- COMPLETED
- UNKNOWN

State precedence:

1. BLOCKED
2. UNKNOWN
3. WAITING
4. WORKING / REVIEWING
5. COMPLETED
6. ACTIVATED
7. IDLE

A member cannot show COMPLETED if the backing object is UNKNOWN.

## Semantic color handling

Identity color and operational state are separate.

Preserve the reference multicolor medallion family at restrained coverage.

Operational state remains authoritative:

- Blue — active work;
- Green — verified/completed;
- Gold — Owner attention;
- Coral — blocker/risk;
- Violet — reasoning/unknown/discovery;
- Cyan — tool/connection context.

A stable member tint may remain visible while state ring/badge communicates current status.

## Reasoning rings

Reasoning rings are shown only when:

- the role/task uses a reasoning-capable model;
- current effort is known.

Fast:
1 ring.

Standard:
2 rings.

Deep:
3 rings.

Max:
4 layered rings or equivalent extended treatment.

Unknown/unsupported:
no fabricated depth; show explicit unknown/unsupported state.

Reasoning rings are interactive semantic objects, not decoration.

Click/tap:
open Model & Reasoning Inspector.

## Interaction contract

Desktop:

- hover -> role/function tooltip;
- click -> Role Context drawer;
- keyboard Enter/Space -> same action;
- visible focus ring required.

Android:

- tap -> Role Context sheet;
- long press -> quick actions only if the same actions exist visibly elsewhere.

Role Context always includes:

- why activated;
- current task;
- operational state;
- findings;
- strongest dissent if relevant;
- evidence links;
- model/reasoning when applicable;
- recent contributions to the current project.

Available actions may include:

- Ask about this member's finding;
- Open evidence;
- Open full review;
- inspect contribution history;
- change model/reasoning only when policy and authority permit.

## Routing-path contract

The fine curved/dotted paths visible in the references are functional relationship/routing language.

A path may communicate:

- activation route;
- review dependency;
- artifact/evidence handoff;
- dissent path;
- synthesis path;
- current participating set.

Paths must not be added as decorative flourishes.

Click/hover behavior may expose routing context where implemented.

Inactive unrelated roles should not appear falsely active.

## Motion contract

Activation:

1. routing path appears;
2. state ring activates;
3. member medallion receives active emphasis;
4. Sigil settles.

Working:
low-frequency ring phase motion only.

Reviewing:
bounded scan/rotation cue, never an endless spinner.

Blocked:
working motion stops; blocker badge appears.

Completed:
single verified settle/pulse then static.

Reduced Motion:
all above become direct state changes/fades.

## Compact member clusters

Project cards may show miniature participating-member medallions.

These mini clusters must preserve:

- recognizable role glyph;
- identity tint;
- participant count/ordering where relevant;
- tooltip/context on interaction when space permits.

They must not be replaced by anonymous colored dots.

## Studio acceptance

Reject a member/Sigil implementation if:

- it looks like a generic icon with no stable member identity;
- it removes role label/subtitle where the reference shows them;
- it has no semantic destination;
- it invents a role not supported by product semantics/reference without review;
- it replaces canonical visible glyphs with unrelated symbols;
- it implies unsupported runtime autonomy;
- it requires color alone to be understood;
- it animates continuously without operational meaning;
- it becomes unreadable below 24px;
- it removes routing paths that carry meaning in the reference;
- it turns the Council into a decorative row.

## Final rule

**Member identity + state + reasoning + routing + interaction = one semantic object.**

A role medallion is never merely an icon.
