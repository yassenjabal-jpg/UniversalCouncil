# Canonical Screen Object Inventory

Date: 2026-10-20  
Status: REFERENCE-DERIVED FIDELITY CONTRACT  
Authority: eight pinned canonical images

## Purpose

This inventory prevents semantic compression of the canonical visual direction.

A future visual artifact may not begin from a short prose summary of a screen. It must begin from:

1. its exact canonical parent image;
2. this screen-object inventory;
3. the governing interaction/motion contracts;
4. a bounded allowed delta.

If an object below is omitted, replaced, or merged, the change requires explicit review.

## Common member / Sigil rule

Across all screens:

**member identity + glyph + tint + state + reasoning + routing + interaction = one semantic object.**

Do not replace this with generic iconography.

## Common interaction rule

Every object that appears actionable must have:

- rest;
- hover/focus where applicable;
- pressed/selected;
- disabled + reason;
- loading/unknown;
- verified success only when backed by truth state;
- exact semantic destination/action.

## Common artifact generation gate

Before any new visual job:

- verify canonical parent bytes/hash;
- attach actual parent reference;
- load matching screen inventory;
- inventory all visible member/Sigil objects;
- inventory all persistent chrome;
- record allowed delta;
- prohibit rejected generations as sources.

After rendering:

- record output/hash;
- create side-by-side comparison;
- inspect every required object for omission/substitution;
- perform governance review;
- perform workshop/visual review.

A visually polished but semantically incomplete screen is rejected.
