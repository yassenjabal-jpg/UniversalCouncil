## Purpose

Continue the visual-direction phase from the adopted Living Operations system before production implementation.

This phase proves how the product looks, moves and reacts as one coherent experience.

It does not build real Autopilot or remote authority.

## Visual identity

Locked identity:

Alive + Intelligent + Evidence-Driven + Interactive + Distinctly UniversalCouncil

Design synthesis:

Playful Intelligence + Editorial Clarity + Professional Operational UI + Living Motion Language

## P1 focus

P1 must visually and interactively resolve five flagship moments:

1. Owner Home.
2. Living Project Workspace.
3. Owner Decision Mode.
4. Recovery / Checkpoint / Fork.
5. Project Complete / Work Receipt.

Android companion receives matched semantic treatments after the desktop core direction is coherent.

## Home

Primary:
ماذا تريد أن تنجز؟

Command Composer is the highest visual priority.

Secondary sequence:
- Since You Were Away.
- Needs Your Decision.
- Pulse Strip.
- Active Work.
- Recent Results.

When no Owner action is needed:
Autopilot يعمل — لا يوجد شيء مطلوب منك الآن.

Do not let System/Tailscale/infrastructure dominate Home.

## Living Project Workspace

Primary focus:
current project state.

Center:
adaptive project artifact/work area.

Around it:
- active Role Sigils;
- Autopilot Current;
- Project Filmstrip;
- evidence;
- Decision Stack;
- tools;
- checkpoints;
- branches.

Only active/relevant objects receive strong emphasis.

## Role Sigils

P1 uses abstract Sigils, not people/mascots.

Every Sigil is interactive.

Click:
Role Context.

Reasoning rings:
click -> Model/Reasoning inspector.

Idle Sigils must not animate as if working.

## Animation

Required signature motions:
- Role activation route.
- artifact handoff.
- Filmstrip insertion.
- Decision focus transition.
- recovery rewind.
- checkpoint pulse.
- fork split.
- Work Receipt completion settle.

No animation without real/prototype event state.

Reduced Motion must provide equivalent state understanding.

## Interactive semantic law

Every visually actionable object must:
- perform an action;
- open context;
- or be explicitly disabled with reason.

No decorative affordance.

## Project Filmstrip

Must feel like the project's visual history, not a tiny audit widget.

Reference sequence:
Before
→ UX Revision
→ Red Team Return
→ Revision 2
→ VERIFIED

Each frame:
- artifact preview;
- timestamp;
- role/tool source;
- truth state;
- click behavior.

## Decision Mode

When Owner action is required:
- background decreases in hierarchy;
- Decision Surface becomes primary;
- recommendation visible;
- strongest dissent visible;
- evidence visible;
- consequences visible.

Actions:
- Approve.
- Request Changes.
- Reject.
- Ask.
- Inspect Evidence.

## Fork / Recovery signature

Fork must become one of the product's recognizable identity elements.

Show:
checkpoint
→ A / B split
→ branch artifacts
→ compare
→ selected branch

Recovery:
current path pauses
→ verified checkpoint focus
→ bounded rewind
→ resume only after verified restored state.
