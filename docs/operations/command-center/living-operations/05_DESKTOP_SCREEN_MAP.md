5. بانتظارك

- notification indicator.

## Screen D1 — Home / Owner Workspace

Order:
1. Command Composer — "ماذا تريد أن تنجز؟"
2. Since You Were Away
3. Needs Your Decision
4. Pulse strip
5. Active Work
6. Recent Results

Composer:
- Council / Studio / Auto;
- model;
- reasoning;
- attachments;
- Start.

Idle truth:
"Autopilot يعمل — لا يوجد شيء مطلوب منك الآن" only when true.

## Screen D2 — Today

Goal:
understand the day in under 30 seconds.

Show:
- 3 most important changes;
- Owner decisions;
- milestones;
- one useful Wild Card;
- one material unresolved Unknown.

## Screen D3 — Projects Index

Each project card:
- project type;
- current stage;
- Autopilot state;
- key blocker/decision;
- small artifact preview;
- latest truth badge.

No KPI grid.

## Screen D4 — Living Project Workspace

The richest core screen.

Header:
- project identity;
- project state;
- current stage;
- owner decision;
- model policy.

Primary body:
- adaptive artifact center;
- Autopilot Rail;
- active roles;
- Filmstrip;
- Decision Stack;
- current tools;
- evidence.

Context drawers:
- Role;
- Tool;
- Evidence;
- Model/Reasoning;
- Version;
- Checkpoint.

## Screen D5 — Software Project Mode

Center:
- diff/branch/worktree state.

Supporting:
- build/test;
- CI;
- runtime evidence;
- checkpoint timeline;
- branch comparison;
- fork action.

Owner action:
- choose branch;
- request fix;
- approve merge gate only where authority allows.

## Screen D6 — Studio Video Project

Center:
- video preview;
- timeline;
- waveform;
- markers;
- variants.

Pipeline:
Writing -> Pre-production -> Production.

Current production department emphasized.

Handoff and Return Ticket visible.

Tool inspector links to Premiere/AE/Photoshop only through implemented authorized actions.

## Screen D7 — Council Decision Mode

Focus surface:
- central decision;
- why now;
- activated Role Sigils;
- recommendation;
- strongest dissent;
- evidence;
- approve/reject impact.

Background project remains visible but de-emphasized.

## Screen D8 — Checkpoint / Recovery / Fork

Timeline:
- checkpoints;
- recovery events;
- branch splits;
- current state.

Actions:
- inspect checkpoint;
- compare;
- create branch;
- governed recovery request.

Default is non-destructive fork.

## Screen D9 — Pulse / Project Story

Visual-first timeline of meaningful project change.

Filters:
- achievements;
- blockers;
- unknowns;
- handoffs;
- decisions;
- before/after.

No social metrics.

## Screen D10 — Council View

Show:
- role registry;
- current reviews;
- why roles activated;
- findings/dissent;
- evidence;
- decisions.

Do not imply independent processes that do not exist.

## Screen D11 — Studio View

Pipeline view:
- Writing;
- Pre-production;
- Production.

For active project:
- current department;
- input;
- artifact;
- primary program;
- QC;
- handoff;
- return tickets.

## Screen D12 — Waiting for You

One decision per low-density card.

Actions:
- approve;
- request changes;
- reject;
- ask;
- inspect evidence.

## Screen D13 — Results / Work Receipts

Project completion receipts with final artifacts and evidence.

## Screen D14 — System

Advanced:
- Tool inventory;
- models/providers;
- Memory Fabric;
- Evidence Bus;
- Remote Owner;
- YASSIN;
- Tailscale/transport;
- execution gates;
- logs/health.

Truth states:
Connected / Ready / Unknown / Blocked.

No infrastructure detail on Home unless decision-changing.

## Core navigation acceptance

A new Owner must be able to:
1. open app;
2. enter request;
3. understand route/plan;
4. start useful task;
5. see active work;
6. receive meaningful Pulse;
7. respond to decision;
8. inspect project;
9. view Work Receipt;

without learning internal architecture first.
