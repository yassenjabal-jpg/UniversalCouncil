# Studio Supervision Charter — Living Operations

Status: OWNER-DIRECTED DESIGN GOVERNANCE

## Mandate

The Studio supervises implementation fidelity for the Living Operations Visual System across Windows and Android.

This supervision is a governance role. It does not assert that Studio roles are separate humans or independent runtime agents unless implemented and evidenced as such.

## Studio authority

The Studio owns recommendations and review for:
- visual system;
- motion system;
- animation quality;
- interaction choreography;
- component anatomy;
- responsive/platform adaptation;
- media presentation;
- visual consistency;
- final art-direction fidelity.

The Studio may block *design acceptance* when an implementation materially violates the adopted visual/motion contract.

It may not override:
- security;
- execution authority;
- evidence truth;
- Owner final authority;
- Stage gates;
- architecture boundaries.

## Required review roles

### Visual / Art Direction
Checks:
- identity coherence;
- semantic colors;
- Role Sigils;
- depth;
- spacing;
- originality.

### Motion / Interaction
Checks:
- motion conveys meaning;
- no pointless loops;
- correct durations/easing;
- interactive objects are functional;
- Reduced Motion parity.

### UX / Human review
Checks:
- primary focus;
- cognitive load;
- first-use path;
- no dead surfaces;
- discoverability;
- keyboard/touch access.

### Evidence review
Checks:
- truth badges;
- evidence peek;
- no fabricated completion/activity;
- UNKNOWN remains UNKNOWN.

### Red Team
Checks:
- misleading affordance;
- decorative complexity;
- false personality/agent implication;
- animation overload;
- accidental destructive gestures.

### Risk/Security
Checks:
- mobile privacy;
- destructive confirmation;
- session/authority language;
- notification leakage.

## Review cycle

Every major surface passes:

1. Static composition review.
2. Interaction map review.
3. Motion storyboard review.
4. Functional prototype review.
5. Truth/evidence review.
6. Accessibility/reduced-motion review.
7. performance review.
8. cross-platform consistency review when applicable.
9. Studio acceptance recommendation.

## Artifact requirements

Before implementation of a major screen:
- annotated screen;
- component inventory;
- interaction map;
- motion storyboard;
- data/truth states;
- empty/blocked/error states.

Before merge:
- screenshots or visual capture;
- motion capture for animated flows;
- list of implemented semantic interactions;
- disabled/blocked state evidence;
- performance notes;
- reduced-motion evidence.

## Change control

A change that modifies:
- semantic colors;
- Role Sigil grammar;
- navigation hierarchy;
- Motion DNA;
- Project Filmstrip behavior;
- Decision Mode;
- evidence truth presentation;
- Autopilot visual semantics;

requires Studio review.

Local spacing/copy fixes do not require reopening the entire art direction.

## No imitation rule

The reference video remains inspiration only.

Studio must reject:
- copied room composition;
- copied characters;
- copied palette;
- copied card shapes;
- copied mascot behavior;
- visually derivative layout.

## Definition of fidelity

A compliant implementation remains recognizable as UniversalCouncil without relying on the logo because of:
- Role Sigils;
- living rails;
- Filmstrip;
- semantic truth badges;
- checkpoint/fork visualization;
- Decision Mode;
- Evidence Peek;
- interactive operational objects;
- restrained Living Motion.
