# Living Operations — Reference-Only Visual Lock

Date: 2026-10-19
Status: OWNER-DIRECTIVE / AL-MURTAKAZ VISUAL SOURCE OF TRUTH

## Supreme visual rule

The eight approved reference images from the current design sequence are the ONLY visual source of truth for the Command Center visual direction.

No new concept may invent:
- a new palette;
- a new layout language;
- new card geometry;
- new decorative motifs;
- new character/avatar treatment;
- new density model;
- new Role Sigil grammar;
- new motion personality;
- new spatial hierarchy

unless a deliberate visual-direction change is separately reviewed and approved by المرتكز.

Textual design documents describe behavior and constraints.
They do NOT override the approved reference images.

## Reference precedence

When there is conflict:

1. Approved reference images.
2. Explicit Owner visual directive.
3. Living Operations interaction/motion contracts.
4. Component and design-token documentation.
5. Any newly generated exploratory image.

A lower layer may not visually override a higher layer.

## Visual derivation rule

Any new screen must visibly derive from the reference set.

It must preserve, where applicable:
- light-first editorial workspace;
- restrained semantic colors;
- high craft but professional operational density;
- distinctive abstract Role Sigils;
- Project-first composition;
- Filmstrip language;
- Autopilot current/rail language;
- contextual evidence surfaces;
- Decision Mode hierarchy;
- checkpoint/fork visual grammar;
- restrained depth;
- visual rhythm and spacing;
- Arabic RTL-first composition;
- no generic KPI dashboard drift.

## Forbidden visual drift

Reject automatically:
- dark neon/cyberpunk restyling;
- architecture/landscape decorative themes;
- human portrait role avatars replacing Sigils;
- generic enterprise/SaaS dashboard grids;
- gold luxury dashboard restyling;
- mascot-heavy presentation;
- decorative continuous animation;
- decorative objects that have no semantic action;
- imagery unrelated to the project artifact;
- redesigning the product from prose while ignoring the references.

## Rejected outputs

The recent exploratory generations that departed from the canonical references are classified:

`REJECTED_VISUAL_DRIFT`

They are not:

## New generation protocol

Before generating any new visual:

1. identify which canonical reference screen is the nearest parent;
2. preserve its composition grammar;
3. specify only the delta required for the new screen/state;
4. do not restyle the whole product;
5. compare output against the parent reference;
6. submit to المرتكز;
7. accept only if verdict is `APPROVED_BY_AL_MURTAKAZ`.

## Editing rule

Prefer visual continuation/editing from an existing approved reference over text-to-image reinvention whenever the target is a variant/state of an existing screen.

## Murtakaz review

Any generated visual is automatically:

`MURTAKAZ_REVIEW_REQUIRED`

until reviewed.

Possible outcomes:
- APPROVED_BY_AL_MURTAKAZ
- RETURNED_FOR_CHANGES
- REJECTED_VISUAL_DRIFT

No generated screen may become a project reference simply because it was generated successfully.

## Final rule

**Reference first. Delta second. No visual reinvention.**

## Durable references and review evidence

All eight canonical images are now stored under `references/` with SHA-256 in the manifest. Verify bytes before visual work; missing or mismatched bytes block work. Conversation IDs alone are insufficient. The owner reattached these images on 2026-10-19; equivalence to unavailable older upload bytes is not claimed.

Each visual job must record its parent role/hash, actual reference attachment, bounded delta, output/hash, side-by-side comparison evidence and review status in manifest `visual_jobs`. Approval additionally requires governance and workshop review records. A boolean or a passing integrity test is not visual approval. New outputs cannot modify the canonical set automatically.

Static reference halos, pastel gradients and role identity colors are permitted and must be preserved. Media thumbnails may contain people/architecture; the prohibition concerns UI chrome and human role portraits. Static images establish no animation duration or easing: motion remains a separately reviewed interaction contract.
